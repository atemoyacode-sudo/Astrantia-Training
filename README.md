# Astrantia: cutting Qwen3.5-35B-A3B to 9.4B and keeping it a Mixture of Experts

Code for **Sharpen-Qwen-3.5-9B-A2.6B-Preview** (code name Astrantia), a research preview released on Hugging Face:
Qwen3.5-35B-A3B cut to 9.4B parameters (−73%), still an MoE with about 2.6B parameters active per token, healed with
about 15M tokens of LoRA training. Not an official Qwen model.

The question behind it: **can a model of any chosen size be made from a large one by cutting it and healing it a
little?** And when it can, **what gets weaker?** The weights, the benchmark numbers and the known weak points are on
the model card: [Takenoko12345678/Sharpen-Qwen-3.5-9B-A2.6B-Preview](https://huggingface.co/Takenoko12345678/Sharpen-Qwen-3.5-9B-A2.6B-Preview)
(and [`-padded`](https://huggingface.co/Takenoko12345678/Sharpen-Qwen-3.5-9B-A2.6B-Preview-padded) for vLLM / transformers).

This repository holds the code of the pipeline that produced the released model, separated from the earlier
experiments, with the training data in one file. The weights are on Hugging Face.

## Results in one table (bf16, thinking on, up to 32,768 tokens, one sample per question)

| | Astrantia (9.4B) | NeoHorse-1-9B | Qwen3.5-9B |
|---|---:|---:|---:|
| AIME 2026 (30 problems, mean of 3 samples) | 20.7 | 20.3 | 22.3 |
| MMLU-Pro (280 of 12,032: 20 per subject) | 144 | 221 | 226 |
| LiveCodeBench v6 (the 175 problems added in v6) | 68 | 96 | 87 |
| IFEval (541, strict) | 362 | | |

Reduced sets, one sample each: see the model card for what that means. The 280 MMLU-Pro questions were also used
(thinking off) to choose among our own runs, so they are not fresh for Astrantia.

## The pipeline

Every step was designed and given its pass/fail rule before it ran. The numbers in brackets are where the step ran.

### 1. Statistics and the cut (`moe/`)

- `moe/build_shape.py --source Qwen/Qwen3.5-35B-A3B --run <dir with data.npz> --shapes g128b28160 --out <dir>`
  - One pass of the original over chat calibration windows records, per layer, how much router mass each expert
    gets and how important each of its neurons is (`stats.npz`; later cuts reuse it with `--from-stats`, no GPU).
  - `g128b28160` keeps the most important neurons among the top 128 experts of each layer, 28,160 neurons per layer
    in total (the parameter count of Qwen3.5-9B). Experts end up with different widths (`moe/width_pass.py`).
  - The result is an ordinary Qwen3.5-MoE checkpoint with placeholder experts plus one file per layer with the real,
    uneven experts (`moe/uneven.py`). It reads the original over HTTP (`remote_st.py`), so no full download is needed.
  - [Kaggle CPU: `heal/kaggle/build_uneven`; or the GPU in `heal/colab_honesty_b.sh`]
- `moe/mlx_kl.py`, `mac_shape.sh`: KL of a cut to the original on held-out chat windows, on a Mac (MLX).

### 2. Healing step 1: the original's own answers (~6M tokens)

- `heal/build_prompts.py`: 9,000 questions (math, science, code) from public training sets, with any question that
  shares a 13-word run with a benchmark question dropped.
- `heal/kaggle/teacher`: the original model (Q4_K_M GGUF, llama.cpp, 2x T4) answers them with thinking on.
- `heal/heal_train.py` with `moe/lora_train.py`: LoRA (rank 16) on attention, Gated DeltaNet and the shared expert;
  routers and routed experts fixed. Loss: cross-entropy on the teacher's answers (sequence-level distillation); half
  of the tokens are UltraChat answers regenerated by the same original. KL to the original on held-out chat windows
  is measured at every milestone. A "loop-exit" phase (`--loop-exit`) adds the
  teacher's answers with a stretch of thinking repeated and a break-out sentence, loss on the break-out only.
  [Kaggle 2x T4: `heal/kaggle/train`, `heal/kaggle/train_uneven`]
- The LoRA touches only layers that are the same in every cut, so the LoRA trained on an earlier uniform cut was used
  on `g128b28160` as is (it scored the same as one trained on the uneven cut itself).

### 3. Healing step 2: Wikipedia text and language answers (~5.4M tokens)

- `heal/wiki_text.py`: plain Wikipedia text (half English and Japanese, half 22 other large Wikipedias), 40% of the
  tokens; `heal/lang_data.py`: answers in other languages (people's prompts from the Aya dataset, and UltraChat
  prompts with a request to answer in another language, answered by the original).
- `heal/colab_wiki_l.sh` (runs `heal/colab_honesty_c.sh`): the same training, started from step 1's LoRA. [Colab G4]

### 4. Healing step 3: facts it knows, facts it gets wrong, and "I don't know" (~3.3M tokens)

- `heal/honesty_data.py label3` labels facts by five stored samples of the model: known (4-5 right), repeatedly wrong
  (trained with the original's right answer), scattered (trained with "I don't know"). `build` mixes them with the
  original's code, math and science answers (`traces_mix3.jsonl`).
- `heal/colab_wikila.sh`: the same training, started from step 2's LoRA. [Colab G4]

### 5. Export

- `heal/fold_lora_uneven.py`: folds the LoRA into the uneven checkpoint, shard by shard (no model load).
- `moe/pad_uneven.py`: writes a plain 128-expert checkpoint for vLLM and transformers. Missing neurons are zero rows;
  a layer with fewer experts gets dummy experts whose router rows are pushed far under the 8th logit on every
  calibration token, then checked on held-out text (0 dummy picks).
- `heal/kaggle/release`: fold → KL check against the training run's own number → upload; `MODE = "gguf"` converts the
  padded checkpoint with llama.cpp to Q4_K_M. `heal/kaggle/gguf_check`: a short llama.cpp check of the GGUF.
- `release/hf/load_uneven.py`: loads the uneven checkpoint with plain transformers plus `moe/uneven.py`.
- `moe/build_uneven_mlx.py`, `moe/mlx_qwen3_5_moe_uneven.py`, `heal/to_mlx_adapter.py`: the 4-bit MLX build used for
  evaluation on a Mac.

### 6. Evaluation

- `fix_task/eval_chat.py`: asks a model (any OpenAI-compatible server, or transformers) a task file and grades it;
  code answers are run only with `--allow-exec`, on a disposable VM.
- `heal/think_cap.py`: the same answers with thinking capped (default 8,192 tokens), then finished by the model.
- `bench/ext_bench.py`: AIME 2026, MMLU-Pro, LiveCodeBench v6 and IFEval (`make` builds the sets, `grade` grades).
  `bench/colab_ext2.sh`, `bench/colab_ext_par.sh`: the G4 runs (vLLM, bf16).
- `heal/halluc_probe.py` (made-up names and short facts; `fix_task/halluc_set*.jsonl`), `bench/lang_probe.py`
  (answers in the language asked), `fix_task/ja_sample.jsonl` (two Japanese prompts).
- `heal/mac_eval.sh`, `heal/mlx_safe_server.py`, `heal/mem_guard.sh`: evaluation on a Mac with a memory guard.

## Data

- **The training rows of all three healing steps are in one file: [`data/astrantia_train.jsonl.gz`](data/)**
  (5,278 rows; what each part is, its fields and the sources' licenses are in [`data/README.md`](data/README.md)).
- Not in it, because they are public or made by a script: the UltraChat answers regenerated by the original
  (`jiapingW/qwen3.5-35b-a3b-ultrachat-regen`), the Wikipedia text of step 2 (`heal/wiki_text.py`, CC BY-SA 4.0), and
  the loop-exit rows (made from the step 1 rows during training).
- The calibration and held-out windows (`stats.npz`, `data.npz`, `teacher.npz`) are made by `moe/build_shape.py` and
  the scripts it imports. The probe sets are included (`fix_task/halluc_set*.jsonl`, `fix_task/ja_sample.jsonl`).
- The benchmark sets (MMLU-Pro, MATH-500, HumanEval, AIME 2026, LiveCodeBench, IFEval) are downloaded by the scripts
  from their public sources and are not redistributed here.

## Hardware it ran on

Kaggle (2x T4, CPU), Google Colab (one G4 GPU, 96 GB), and a Mac with 32 GB for MLX evaluation. Paths in the
scripts follow that layout (`/kaggle/input`, `/content`, a local `cache/`), and Kaggle / Hugging Face account names
are written as `<kaggle-user>`.
